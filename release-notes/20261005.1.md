The first AVXEmu release with changes to the emulator itself.

- **Thread-safe relocation.** When a hot site moves into the code cache while other threads
  are running it, those threads keep going. Before, a multi-threaded program could crash there
  with `SIGILL` or `SIGBUS`.
- **Load-time patching keeps `__text` executable**, and avxemu keeps its own `cpuid` out of what
  it patches. A program that links avxemu into itself no longer crashes before `main`. On macOS
  newer than 10.9, an inserted avxemu now patches the program, not itself.
- **Inert where there is nothing to emulate.** On a CPU that has AVX2, FMA, BMI1, BMI2, LZCNT,
  F16C and MOVBE, avxemu loads and does nothing else, so it is safe to link it everywhere.
- **Cached load-time analysis.** The first launch of a program records what the load-time passes
  decided, in `~/Library/Caches/avxemu`, and later launches replay it. Claude Code's process
  start went from about 2.2 s to 0.04 s (measured 2026-09-25 on Mac OS X 10.9 without AVX2).
  `AVXEMU_NOCACHE=1` turns the cache off.
- **Faster register-operand BMI.** The minimal-spill tier and the native MULX thunk are on by
  default. `AVXEMU_MINSPILL=0` turns off the tier; `AVXEMU_NATIVE=0` turns off the native
  thunks, MULX included.

Checked on Mac OS X 10.9 without AVX2: the released `libavxemu.dylib` passes its self-test
(`AVXEMU_SELFTEST`) and runs Claude Code. Its `hardware` tests pass on an Intel Mac with AVX2,
FMA and BMI.
